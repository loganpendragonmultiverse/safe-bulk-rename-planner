# Security policy

Please report a vulnerability through GitHub's private vulnerability reporting feature instead of opening a public issue. Include the affected version, operating system, reproduction steps, impact, and any suggested mitigation.

The most sensitive areas are path containment, collision handling, symbolic links, hash verification, two-phase rename recovery, and manifest tampering. Do not include private filenames or file contents beyond the minimum synthetic example needed to reproduce a problem.

Only the latest release receives security fixes. No response-time guarantee is offered, but credible reports will be acknowledged and assessed as promptly as practical.
